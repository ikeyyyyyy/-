## P4 · 目标与设计原则

**四个"必须有"**：

1. **零部署**：双击 HTML 就能跑，课堂演示不能翻车
2. **可诊断**：分数要能拆到维度，问题要能指回原句
3. **多体系**：六套评分框架，权重与档位可切换
4. **有边界**：明确标注"AI 参考分"，不假装自己是阅卷老师

> 视觉：四个图标 + 短句，2×2 排列。
> 口播：第三条和第４条是我最坚持的，等下会重点讲。

## P7 · 核心设计②：诊断规则怎么"看见"错误

**左边：规则示例（代码片段截图）**

```js
// 主谓一致：people/they + is/was/has
/\b(people|they|students)\s+(is|was|has)\b/gi
// 冠词：a + 元音开头（排除 a university）
/\ba\s+([aeiou]\w*)/gi
```

**右边：检出结果（真实运行截图）**

- 拼写：`goverment → government`
- 语法：`there is many`（主谓不一致）
- 语法：`have also build`（应为过去分词）
- 词汇：`good ×2`（用词笼统）

**关键句**：每条规则都要输出**原文片段**，评语才不空。

> 视觉：左代码右结果，中间一个放大镜图标。
> 口播：这就是"可解释"的具体含义。

## P8 · 核心设计③：分数如何避免"虚高"

**三个校准机制**（三条并列）：

1. **字数曲线扣分**：`0.9 × (实际/要求)^1.6`，写得越少掉得越快
2. **交叉影响**：语法+词汇达成率 < 0.7 时，内容与结构分一起打折
3. **不给满分**：单维度上限 = 满分 − 0.5；总分向下取整

**副标**：宁可保守，不做"AI 说你这篇完美"。

> 视觉：三条并列卡片 + 一条下降曲线示意。
> 口播：这三点是我调试时反复调整的地方，也是我认为最像"真人阅卷"的部分。

## P11 · 局限与反思

**四条坦白的局限**：

1. **不懂立意**：能数衔接词，判断不了论点深度
2. **模式匹配**：语法检查会漏报、会误报
3. **分数是坐标**：不是考场分数，阅卷员之间也有 1–2 分差异
4. **覆盖面有限**：不含雅思 Task 1、托福综合写作

**一句总结**：它的定位是**写作体检报告**，不是判决书。

> 视觉：四条 + 底部免责声明截图（页面顶部那条黄色提示）。
> 口播：主动讲局限，比被提问时再解释更有说服力。

## 附：PPT 制作提示

- **字号**：标题 40–44pt，正文 20–24pt，表格 16–18pt，**不要小于 14pt**；
- **配色**：主色 `#0EA5E9`，辅色 `#22C55E`（正向）/ `#F43F5E`（问题），背景白或 `#F5F9FD`；
- **每页只讲一件事**，字越少越好，代码页只放 3–5 行关键片段；
- **截图统一宽度**，加 `8px` 圆角和淡阴影，视觉整齐度立刻提升；
- 演示前把浏览器窗口调到 **1280×800**，并把页面滚动到顶部，避免投屏时字号过小。

### P16 · 学习档案：把 22 个错误类别变成一条曲线
